## Data flow
AIS receiver (external existing service) -> live.py (single worker; snapshot, normalizer in events.py) -> live_events.py OperationalTracker -> engine.py frozen predictions -> evaluation.py trip journal / publication. Trajectory reader in trajectories.py shares geometry and associates historical observation timestamps to journal intervals; unmatched observations are partial. No second event tracker in runtime. Historical Tracker remains solely in tests/legacy_tracker.py for comparison. API endpoints, public.html and model calculations unchanged. Snapshot is read under worker lock; source rows may still be rejected or awaiting a valid event. Quality and timing provenance retained separately. Durable departure outbox persists with trip journal before idempotent ledger departure. Stockflow caches only two port summaries, invalidates by SQLite data_version and time/heartbeat boundaries, refreshes at most 60 seconds. Existing vehicle/CCTV credentials and relay not changed.
