# Stages 12–14 — gated release
1. Run synthetic tests. Validate actual models with validate_release.py against independently exported Local Run fixture (>=10 cases per role, tolerance 1e-6 minute), exact dependency versions and hashes. This is component parity only; replay raw AIS to compare event timing/features/ETD, then observe both systems through real cycles. No claim of validation until executed.
2. stage_install.sh installs loopback-only staging as unprivileged user, bounded CPU and memory; no public route, no legacy change. Initial diagnostic uses legacy Python read-only; install separate pinned venv before actual model activation. If read access fails, stop; do not chmod legacy source automatically. Access via SSH tunnel. Stock initial and capacity policies must be configured; capacity PCE and motor equivalents/fill fractions require operator approval. CAPACITY_POLICY is retained internally; dashboard labels outflow as capacity-based, not observed manifest. Missing policy leaves departure pending.
3. Before production switch: resolve archive service failure via journal, verify next successful daily upload and exit status; verify raw receiver and timer remain active, check resource headroom; validate model/event parity, CCTV delivery, overnight reset, departures, dashboard and authentication. Preserve legacy services and config. Obtain actual nginx config and existing auth routes before authoring public routing; do not replace entire nginx config or disable legacy services. Back up nginx and test nginx -t before reload; rollback by restoring previous routing. Public cutover is blocked until these gates pass. No destructive migration of MariaDB or AIS data.
