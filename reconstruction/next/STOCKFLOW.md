# Stock-flow operational contract
Per terminal and vehicle class: opening + cumulative arrival increments - departure loads. Counter resets daily WIB; stock persists. Opening stock and matching CCTV counter at the observation time must be entered explicitly using stock_admin.py. Only actual confirmed load or explicitly labelled estimated load is accepted. No automatic capacity allocation: repository PCE capacities are unverified and do not identify class mix. Unknown loads, negative balance, missing days and stale transport suppress the numeric queue. Partial stock is diagnostic only. A departure D0 from AIS triggers one durable ID (MMSI + UTC event + port); duplicate events cannot subtract twice. AIS inference is provisional. No physical ramp timestamps claimed.
The receiver is authenticated using BIMA2_VEHICLE_TOKEN set outside Git. Only observed payloads accepted; mode is a sender declaration, not proof. Use isolated HTTPS endpoint after staging validation. Campus sender reads existing observed daily CSVs without changing archives, replays every row and retries. Use --since with the opening day. It must not be pointed at simulation data. Heartbeat measures sender communication, not camera health. Camera outage and missing final CSV rows need independent monitoring. No outflow inferred from capacity. Local admin CLI only for opening and departure loads; no public write endpoint. No production changes.
